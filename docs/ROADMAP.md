## A1. 输入与资源保护的长期要求

1. 扩展名、路径、文件头、用户声明和内部磁盘 JSON 都不能代替验证。先验证实际常规文件对象、数量和大小，再有界探测编码、表头与结构；明显超限输入在读取正文、哈希、复制或备份前拒绝。
2. 持续限制实际读取字节、行长、字段长、列数、物理行数、观测数、JSON 大小/深度、错误样本、目标整点、动作候选、绘图点数和输出量。文件增长/替换及多次追加不能绕过预算。不得无限 read/readline/splitlines，也不得只校验头部。
3. 资源策略集中在 `input_policy.InputLimits`；当前值及含义见 USER_GUIDE 第 11.3 节。流式读入不消除排序、去重、索引和曲线的后续内存成本，所有入口及下游处理均须有界。
4. 文件名、路径、错误和头部按普通文字显示；进入富文本前转义，不拼入 shell 或动态代码。后台处理支持安全取消/超时，诊断有上限；保存提交阶段不得强杀工作进程。
5. 格式错误、容量拒绝、权限/文件变化、超时及用户取消分别报告。禁止截断后导出为完整成功；拒绝与取消不破坏原始数据，不留下孤儿进程或持续写盘。
6. 小型夹具、可注入预算和受控流覆盖上限前/上限/上限后、伪装二进制、无换行巨行、NaN/Inf、重复声明、正文结构错误、文件变化、慢 IO 与磁盘满等路径，不实际制造 TB 文件或千万行数据。

## A2. 业务规模与测点完整性

- 72 小时、通常低于 1 Hz、约 72 次断电仅是资源估算参考，不是时长、频率或文件数量的业务硬限制。安全预算依据累计字节、行数、文件/目录项、计算和输出成本设置并留合理余量；长时间稀疏数据还须预算目标整点数量。
- 文件选择/目录枚举先有界，再提交清单；追加、重复路径和别名计入相应预算。超限选择整体拒绝，保留原列表，不默默取前 N 个，也不编造未枚举的总数。
- 每份 DAT 按自身表头解析。相同测点中任一必需文件损坏、缺必需列或超预算，阻止该测点本次处理；保留文件归属和失败原因，不跳过坏文件制造完整结果。其他合法测点可独立成功，整批明确部分失败。
- 旧结果及其输入/规则快照保留并标明已过时；用户主动修正/移除文件后重新校验。最后一份文件失败时，不留下本次半份 CSV 冒充成功。
- 性能与容量变更应提供可复现的问题、代表样本、资源开销和兼容性依据；同时验证正常结果、超限拒绝、安全取消和交互响应。资源估算示例不代表已支持该规模。

## 编辑、校正与帮助维护

- 水深、规则、时间等编辑只操作草稿；未勾选修改、取消、Esc 和关闭不提交，确定时整体校验并原子应用。固定层数/自定义层位不被自动推荐覆盖，历史结果不随草稿变化。
- 统一复用 Fluent 控件、单点/批量编辑逻辑和日期时间浮层；公共组件同时检查所有使用窗口的外观与行为。水深“处理时自动估算”只在处理时读取数据，模式记忆只在当前对话框生存。
- 时间校正限显式选择的单文件：前三步只读预览，第四步最终确认，先建立不覆盖已有文件的完整备份，再安全替换并复验；失败回滚/另存。分析输入、参数或缺测分配变化立即作废旧写入许可。已知关系和整点匹配都只作全局时间平移。
- 普通处理不改原 DAT。校正成功后相关缓存失效，人工水深与历史快照保留，用户重新处理生成新结果；另存不自动替换主测点文件关联。
- 用户帮助与界面事实参考分别维护。当前帮助待核对：整点模式分秒固定；局部候选与完整动作的区别；分界不明时只读拒绝；明细原始时刻与平移后曲线的区别；换文件保留草稿但旧确认失效。以当前源码和 USER_GUIDE 第 12 节为准。
