# OBS 数据处理工具：界面、操作与处理行为事实参考

## 1. 本文用途与版本边界

本文描述当前源码的界面与处理行为，包含 DAT 列识别与“实用工具→时间校正”。项目状态与待验收事项见 ROADMAP。

本文面向开发者和帮助文档维护者，是编写用户帮助的事实参考。即使不阅读源码或运行程序，读者也应能理解主要界面、操作顺序、输入含义、结果解释和限制。

右上角“帮助”面向最终用户，其文案可以据本文重新组织、精简和润色，但不能把未实现功能写成已有功能，也不能把内部实现说明变成用户操作要求。本文保留必要的技术说明，并在末尾提供实现索引。

源码与具体 EXE 按精确构建提交区分，不能仅凭版本号判断包含哪些改动。本文是开发者事实参考，不作为最终用户帮助随 EXE 交付；每次发布前按实际源码核对帮助。

程序主要用于本地 OBS DAT 观测数据处理：按测点组织原始文件，以整点为目标时间，按指定水深和分层方案选择原始观测，生成 CSV，并通过曲线及来源信息核查结果。它不是录屏软件，也不是自动生成连续海洋剖面或修复缺测数据的工具。

## 2. 启动、主界面与术语

软件统一名称为“OBS 数据处理工具”：主窗口标题显示名称与版本号，左上角标题和“帮助→关于”显示同一名称。后续构建文件名为 `OBS 数据处理工具-<版本号>-preview.exe`，整理到 GitHub 交付时使用 `OBS-Data-Tool-<版本号>-preview.exe`。发布版双击 EXE 运行，不要求用户安装 Python 或手动解压依赖，首次启动可能稍候。源码开发入口为根目录“启动开发版.cmd”或 `pwsh -File scripts/dev.ps1 gui`，这两项不是最终用户操作步骤。主要目标系统是 Windows 10/11；真实无 Python 目标电脑、系统 DPI 切换和多屏等仍有待验收，不能写成已在所有电脑验证通过。

主界面右上角为“实用工具”“帮助”“高级设置”；中间有“数据与设置”“处理结果”两页；底部显示状态、处理时的进度和“取消任务”。“帮助”内有“使用帮助”“关于”，后者显示版本、作者 zhao0349（链接至 https://github.com/zhao0349）、联系邮箱 zxy0349@qq.com（mailto 链接）、项目地址 https://github.com/zhao0349/obs-tool-oss、反馈问题入口 https://github.com/zhao0349/obs-tool-oss/issues、代码许可 GPL-3.0-or-later、图标许可 CC BY-NC-SA 4.0 和第三方项目链接；邮箱链接调用系统邮件程序，网页链接调用默认浏览器，访问网页需要网络，本地数据处理本身不依赖在线账号。

| 术语 | 本程序中的具体含义 |
|---|---|
| 测点 | 一组具有同一编号、共同水深、分层规则和起止时间设置的输入文件，可包含多个 DAT |
| 水深 H | 本次处理采用的参考水深，单位米；可手工填写或在开始处理时估算；同一测点本次处理使用固定 H，不随潮位逐时变化 |
| 目标整点 | 程序逐小时输出结果的时间，例如 2026-10-16 09:00:00；并非某条原始记录的采样时刻 |
| 观测片段 | 从原始时间序列按深度变化和时间断档等条件识别出的连续观测片段；不等同于一个 DAT 文件 |
| 层位 | 要选取观测的垂向位置，如 0.2H；这是目标位置，选中的原始记录可能与该深度有偏差 |
| 实际采样时间/深度 | 最终选中原始记录里的时间和深度，不会为了与目标整点、目标层位相等而改写 |
| 本次/上次结果 | 当前界面保留的不同运行结果；修改设置不会改写旧结果 |

## 3. “数据与设置”页及数据导入

### 3.1 控件与操作对象

| 入口 | 作用与对象 |
|---|---|
| 添加文件夹 | 选择一个包含 DAT 的文件夹，将其中当前层的 DAT 文件加入列表；不递归扫描子文件夹 |
| 添加 DAT 文件 | 一次选择一个或多个 DAT，可反复追加来自其他文件夹的数据 |
| 开始新一批 | 确认后清空当前测点、勾选、结果预览、日志和进度；不删除原始文件或已生成的 CSV |
| 编辑当前测点 | 编辑当前高亮测点；双击任意非复选框单元格打开同一窗口 |
| 批量设置 | 编辑首列复选框勾选的测点；不是所有高亮行，也不必连续 |
| 设置数据文件 | 修改当前高亮测点所关联的 DAT 文件清单 |
| 勾选全部 / 取消全选 | 切换全体测点的勾选状态；表头复选框也可使用 |
| 更多 | 包含“移除勾选测点（不删除文件）”“清空当前列表（不删除文件）”“恢复默认布局”“查看当前测点水深详情” |
| CSV 保存位置 / 更改 | 显示保存位置，用“更改”打开文件夹选择器，位置文本框不能直接编辑 |
| 开始处理并导出 CSV | 处理当前列表全部测点，自动保存 CSV；不以首列勾选状态限定处理范围 |

测点主表列为：复选框、测点编号、水深 H（米）、水深来源、分层规则与层位、时间范围、数据文件。表头不排序；部分勾选时表头显示部分选中状态。键盘定位复选框后可用空格切换。Ctrl/Shift 产生的多行高亮不替代勾选。

编号和水深单元格还支持编辑键进入编辑，但双击会打开完整测点编辑窗口。编写普通用户帮助时可优先说明明确的“编辑当前测点”入口，不必要求用户知道表格快捷键。

### 3.2 文件名、归组与追加

测点编号取不含扩展名的文件名中第一个 `#` 之前的部分。例如 `1-1#.dat`、`1-1#第一次.dat`、`1-1#第二次.dat` 都归入测点 `1-1`。无 `#` 时，以完整的文件名主体作为编号。扩展名不区分大小写。

同编号的新文件追加到已有测点，不新建同名行；同一路径已加入的文件不重复加入。`S1` 和 `s1` 这种仅大小写不同的编号会被拒绝，应先统一或修改编号。不同文件夹中同编号的文件也会合并，导入后应检查归属。主界面显示测点、文件及文件夹数量，并显示追加数量；必要时查看运行日志中的归组记录。

编号允许字母、数字、汉字、下划线和短横线，不能为空，不允许空格、路径分隔符等其他字符，也不能使用 Windows 保留名称，如 CON、NUL、COM1。修改编号不重命名硬盘上的 DAT。

添加数据不立即分析整批 DAT 或估算水深。系统文件选择器确认之前不读取 DAT 内容。新测点水深留空、来源待估算、规则自动、时间不限定；用户可先把已知水深、时间和分层配置好，再开始处理。

为已有测点追加或更换文件时，人工水深保留；原本依靠自动估算的水深会恢复待估算，原估算详情清除，以便下次处理基于新文件估算。加载文件与更改文件清单都不会立刻启动估算。

### 3.3 设置数据文件、移除与清空

“设置数据文件”窗口显示该点文件路径列表，提供“添加DAT”“移除选中文件”和“应用/取消”。可用 Ctrl/Shift 选择多个文件后移除；操作仅调整本次输入关系，不改动文件。通过此窗口手动添加的文件归到当前测点，不按文件名前缀再次建立其他测点。

点击“应用”保存清单，“取消”丢弃本次清单调整。若把某点文件全部移除，主界面会提示未关联 DAT，不能直接开始整批处理，应重新关联文件或移除该测点。

“移除勾选测点”只从当前列表移除勾选对象；“开始新一批”和“清空当前列表”清空整批，并有确认。清空不是恢复全部参数默认：当前筛选参数、CSV 设置及保存位置仍保留，自定义规则库也保留。

## 4. 单点编辑、批量编辑与提交时机

单点窗口标题为“编辑测点”，包括测点编号、当前水深及来源、水深修改组、分层规则和层位预览、限定开始时间、限定结束时间及观测范围说明。按钮为“应用”“取消”。

批量窗口标题为“批量编辑测点”，顶部说明选中数量，包括水深修改组、“修改分层规则”及选择器、开始和结束时间的操作选择及日期时间输入，按钮同样为“应用”“取消”。批量窗口没有统一修改测点编号的操作。

### 4.1 水深修改组的完整行为

两类窗口共用以下逻辑。已有水深可预填在数值框中，但“框里有值”不等于本次会修改水深。

| 用户操作 | 两个单选按钮的状态 | 水深数值框 | 应用时的效果 |
|---|---|---|---|
| 新打开窗口，未勾选“修改水深” | 均禁用、均不选中 | 禁用 | 保留每个测点原水深与来源 |
| 本窗口首次勾选“修改水深” | 默认选“手动填写” | 启用 | 使用输入的正数水深 |
| 选择“处理时自动估算” | 自动选中、手动未选中 | 禁用 | 清除当前指定水深，改为下次开始处理时估算 |
| 取消“修改水深” | 均禁用、均不选中 | 禁用 | 不修改水深；此前输入的草稿不生效 |
| 同窗口再次勾选 | 恢复本窗口上次选择的手动或自动方式 | 仅手动方式启用 | 按恢复的方式修改 |
| 应用、取消、Esc 或关闭后重新打开 | 回到最初未勾选状态 | 禁用 | 首次勾选仍默认手动，不沿用上个窗口的模式 |

水深单位为米，手工提交必须大于 0；数值框上限为 1,000,000 米。这是控件范围，不是适用海域或仪器能力声明。自动方式不会使用或校验禁用的手工水深草稿，保存时也不读取文件进行估算。

批量手工修改会把同一个数值应用于勾选对象；不勾选“修改水深”则各点保留各自水深。若仅想修改分层规则，不需要同时勾选水深。主表水深单元格清空也可恢复待估算；在编辑窗口中应使用“处理时自动估算”，不要将输入 0 理解成自动。

### 4.2 分层、时间及整体提交

单点分层选择器打开时显示该点当前规则。批量的“修改分层规则”默认不勾选、选择器禁用；启用后选定规则会统一应用于勾选测点。未启用时不得把选择器显示的第一个点规则误认为全批已统一，也不会修改其他点的规则。

单点通过“限定开始时间”“限定结束时间”分别启用相应输入；已有时间限制会显示并勾选。取消某一端勾选表示去掉该端限制。

批量的“开始时间操作”“结束时间操作”各有三种选择：

| 选项 | 效果 |
|---|---|
| 不更改（默认） | 保留每个测点该端原有设置，输入框禁用 |
| 设置时间 | 启用该端输入，统一设置为填写的完整日期时间 |
| 不限定 | 清除勾选测点该端限制，输入框禁用 |

点击“应用”时统一校验本次修改。任何启用字段有误，如水深为 0、编号冲突、时间不完整或开始晚于结束，整次修改不提交，窗口保留填写内容并提示错误。更正后再应用；取消、Esc、标题栏关闭不保存此次修改。设置改变只影响下一次处理，不改写已生成结果。

技术语义：以稳定 `point_id` 关联测点，不靠可编辑编号定位历史结果；提交为原子操作。未勾选修改水深时保留原精度、来源及估算信息，不能把显示精度回写成新人工值。

## 5. 日期时间选择及“时间范围”的真实含义

日期完整显示为年-月-日，时间为 24 小时制时:分:秒，按仪器记录的时间填写，不做时区换算。起止两端可只设置其中一端；任何启用的一端都必须同时具有有效日期和时间。

日历按钮打开定制月历，左右箭头切换页面，年月标题可进入月份/年份选择。选中日期后写入日期部分；未选择即关闭或按 Esc 不修改原值。时钟按钮打开时、分、秒三列滚动选择器，可滚轮、点击邻近值或用方向键调整；“确定”写入时间，“取消”、Esc 或点击外部不保存这次时间选择。日期和时间分别修改，选日期不会替用户补齐时间。也可直接用键盘输入。

当没有已有时间或观测范围可供预填时，显示“选择日期”“选择时间”，不会把当天年份自动作为观测日期写入。原来已限定的时间优先显示；已知观测起止时间可作为编辑建议值。

**起止时间限定的是要生成哪些目标整点，不是先把原始记录裁剪掉再做分段。** 窗口外原始记录仍可参与片段识别和匹配。这一点不能写成“彻底排除范围外原始观测”。

- 未限定开始：从第一条有效观测所在小时开始。例如首条为 08:23，首个目标为 08:00。
- 明确限定开始：向上取整点。例如填写 08:23:00，首个目标为 09:00；填写 08:00:00 则包含 08:00。
- 未限定结束：最后目标为最后有效观测所在小时。
- 明确限定结束：包含不晚于该时间的整点。例如结束 10:30，最后目标为 10:00。
- 因此设置 08:23 至 10:30 会生成 09:00、10:00 两个目标；一个范围内没有整点时可能没有结果行，不会凭空增加非整点结果。
- 显式时间超出文件观测范围时仍可生成这些目标整点，无法匹配时标缺测。开始不能晚于结束；程序限制最多 2,048 个目标整点，用于防止误填跨度，不是建议的工作量。

## 6. 分层规则：选择与管理

### 6.1 系统规则与自动推荐

| 自动选择时的水深区间 | 推荐名称 | 层位 |
|---|---|---|
| 0 < H < 2 米 | 系统规则：1层 | 0.6H |
| 2 ≤ H < 5 米 | 系统规则：2层 | 0.2H、0.8H |
| 5 ≤ H < 8 米 | 系统规则：3层 | 0.2H、0.6H、0.8H |
| 8 ≤ H < 11 米 | 系统规则：5层 | 表层、0.2H、0.6H、0.8H、底层 |
| H ≥ 11 米 | 系统规则：6层 | 表层、0.2H、0.4H、0.6H、0.8H、底层 |

“根据水深自动选择”随 H 决定规则。明确选择某个“系统规则：x层”后层数固定，不再随 H 自动改变，即使选中的正好是当时推荐项。自定义规则也保持其层位比例；水深变化会改变相对层的目标绝对深度。

推荐项后显示“（默认）”，只是推荐，不锁定选择。例如 H=2 米时推荐 2 层，但允许直接选择系统 3 层，不必先创建自定义规则。若要重新跟随水深，明确选回“根据水深自动选择”。批量恢复自动时，每个点按自身水深决定层数，不强制同层数。

编辑时水深草稿会更新推荐标记和预览，不自动替换已选规则。水深未定时自动规则显示待水深确定；批量水深对应的推荐不一致时，不展示一个代表全批的默认项。固定层数仍需有效 H 才能实际处理。

系统表来自此前采用的分层表，规范完整名称和版本尚未确认；不要自行补写国家标准编号、年份或宣称已完成规范符合性认证。

### 6.2 自定义规则的创建、应用和删除

入口为“高级设置 → 分层规则”。该页上方为只读系统规则表，下方为“创建自定义规则”“删除自定义规则”和规则列表；无规则时显示“暂无自定义规则”。这里不再逐测点分配规则。

创建流程：

1. 点击“创建自定义规则”，打开独立窗口。
2. 填“规则名称”，默认取未占用的“自定义规则1”等名称。
3. 在“层位”框输入一个 0～1 的数值，点击“添加到列表”，依次添加其他层位。输入框显示三位小数；列表自动去重、由浅到深排序。
4. 可“移除选中层位”或“清空层位”，下方显示总层数和完整预览。最终须有 1～64 个不同层位。
5. 点击“确定”保存并返回管理页；“取消”不创建。名称或层位不合法时留在窗口，保留已填写内容供修正。
6. 回主界面编辑当前测点，或勾选测点后批量设置，选择刚创建的规则并应用。仅创建规则不会改变任何测点所采用的规则。

0 表示表层选取逻辑，1 表示底层选取逻辑；0.2 等中间数值表示目标深度 0.2×H。表层不是强行制造 0 米记录，底层是片段内最深实测记录，不保证等于 H。输入小于 0.1 或大于 0.9 的层位会显示提示，但不会擅自替换为表层或底层。

名称不可为空、重复或冒用系统/旧版默认规则名称；冲突比较会考虑大小写、全半角及空白。不同名称可以使用相同层位。如果旧规则名称冲突，会出现“调整旧规则名称”，并暂时禁止新建；调整名称不改变层位。

删除前先在自定义规则列表选中一条。当前测点正在使用的规则不能删除，会提示先回主界面为这些点换规则并应用，再打开高级设置删除。未使用规则点击删除后立即保存，不额外等待“应用设置”。

**规则库操作与参数应用的保存时机不同。** 创建窗口“确定”、删除规则、确认调整旧名称都会立即保存规则库；之后在高级设置点击“取消”，不会撤销已经完成的这些操作。筛选参数和 CSV 选项则须点击“应用设置”才提交。保存的自定义规则下次启动可用。旧批次自带但不在当前库中的规则仍可显示、保留；删除库中规则不会篡改旧结果快照。

## 7. 高级设置的筛选参数与 CSV 选项

筛选参数分“片段识别”“整点匹配”“表层选择”“质量检查”。可键盘输入数值，将鼠标停在名称上查看说明。下表为干净启动/恢复默认时的值，不代表所有输入数据都适合这些值。

| 分组 | 界面名称 | 默认值 | 实际作用 |
|---|---|---|---|
| 片段识别 | 片段断档上限（分钟） | 5 | 相邻观测间隔超过上限时分成不同片段 |
| 片段识别 | 前缓冲（分钟） | 8 | 将片段开始前该时间范围内的观测纳入选取 |
| 片段识别 | 后缓冲上限（分钟） | 8 | 限制片段末尾已纳入的低值观测保留时间；不是结束后再读取未来 8 分钟 |
| 片段识别 | 结束所需连续低值（个） | 4 | 达到相应连续低值数量后结束片段 |
| 片段识别 | 最低参考深度（米） | 0.10 | 分段深度阈值不低于此值；不是测点总水深 |
| 整点匹配 | 整点与片段峰值的最大时间差（分钟） | 60 | 最深观测时刻与目标整点的差不超过此值才可匹配，边界包含 |
| 表层选择 | 表层深度下限（米，严格大于） | 0.5 | 表层候选的深度必须严格大于此值 |
| 表层选择 | 表层评分：深度权重 | 1 | 在综合评分中提高对较浅记录的偏好 |
| 表层选择 | 表层评分：距整点时间权重 | 0.1 | 提高对更接近目标整点记录的偏好 |
| 表层选择 | 表层评分：距片段起点权重 | 0.05 | 提高对更接近片段起点记录的偏好 |
| 质量检查 | 启用绝对深度容差 | 未启用 | 启用后按米检查实际与目标深度之差 |
| 质量检查 | 启用相对深度容差 | 未启用 | 启用后按目标层深度的百分比检查，不是总水深 H 的百分比 |

界面中断档上限最小 0.001 分钟，连续低值最小 1 且为整数，其他上述普通数值允许 0；普通参数上限 1,000,000。绝对容差框 0～1,000,000 米，相对容差框 0～100,000%。这些是输入范围而非业务推荐，不能把上限写成合理设置建议。

相对深度容差示例：H=10 米、目标层位 0.2H，则目标深度为 2 米；容差 10% 对应允许偏差 0.2 米，不是 1 米。两种容差都启用时取较严格者；等于上限仍通过。超限值保留并标“深度超差”，不会自动删掉或补一个值。都不启用时显示“未检查深度偏差是否超限”，不能据此认定合格。当前深度容差用于相对层，表层/底层没有另行确立的专业容差判据。

“CSV导出”页：

| 设置 | 选项和效果 |
|---|---|
| CSV编码 | 默认“UTF-8（推荐，Excel可识别）”，实际为带 BOM 的 UTF-8；还可选 GB18030、Windows ANSI |
| 仅导出各层数据齐全的整点 | 默认不勾选；勾选后，缺任一层的整点整行不写入 CSV，不是只删除空单元格 |
| 数值格式 | 保留三位小数，缺测留空；不把缺测填为 0 |

完整性导出选项只影响 CSV，界面仍可核查完整结果中的缺测记录；它也不自动排除复用或深度超差记录。

“应用设置”统一提交筛选参数和 CSV 选项；取消则不提交这些调整。“恢复当前页默认”只作用于当前页：筛选页恢复默认参数并关闭容差；CSV 页恢复 UTF-8 和不勾选完整性过滤；分层页不会删除规则、重设测点，只提示系统规则内置。恢复后的参数还需点击“应用设置”。

## 8. 开始处理、水深确认、取消与重试

先添加输入并核对设置，再确认“CSV 保存位置”，必要时点“更改”；最后点击“开始处理并导出 CSV”。默认保存位置为当前 Windows 用户主目录下的“OBS处理结果”。不得选任何输入 DAT 所在目录或其子目录作为输出。

点击开始前至少需要一个测点、每点关联文件、合法编号和已填写字段、保存位置。未填写水深是合法状态，不妨碍开始。按钮旁会说明将处理列表全部多少个测点；字段有误时会提示原因，修正后再开始。勾选仅用于批量编辑和移除；只想处理部分测点时，应使当前列表只保留这些测点，不能只勾选它们就按开始。

程序先只对水深为空的测点后台估算；全部已有水深时跳过。人工水深优先，不被自动估算覆盖。估算结合多段观测的深度峰值，不能把“某条最大深度”简单等同于总水深；仪器未到达底部时也无法凭数据证明总水深。

可靠的估算继续进入处理；输入格式合法但无法给出水深（如有效观测不足），或建议值需核对时，弹出“水深填写与确认”。无建议值时显示“请填写”，须填入现场实测水深，不用0或其他点水深代填。列为测点、水深（米）、来源、需要确认的原因、确认采用。每一行须填入有效正数或确认已有建议，并勾选“确认”；点击“确认并继续处理”接续本次任务，不必重新导入。遗漏任何一行会提示，不会偷偷跳过；取消停止本次任务。修改建议数值或补填缺失值后来源视为人工填写；仅确认未改变的估算值仍保留估算来源和确认记录。无效值或未勾确认只提示并保留当前草稿；取消、Esc或关闭确认框停止本次任务，恢复编辑、重新处理和开始新一批，不改动已有结果快照。

输入本身无法读取、结构错误或超过资源预算时不要求填水深，不能通过人工水深绕过校验。该点的完整文件集合仍交给正式处理检查，任一必需文件不合格则整点失败，原因记入结果和日志，其他合法点可继续；整批数量或累计字节预算超限仍可拒绝整批。水深准备、表格/结果刷新或后台任务创建与启动异常会结束本次准备并恢复可操作状态；仍有活动任务则先安全取消，等待其结束，不提前启用编辑。取消不等待已结束或从未启动的后台任务。

平时的“N 个测点的水深需要确认 · 查看详情”显示全部需要确认的测点，不受当前高亮或勾选范围影响；“更多 → 查看当前测点水深详情”只看当前点。平时打开的是只读详情，不能在其中填写确认；需要修改时回测点编辑。详情中的“查看技术信息”展示方法、峰值 IQR 等内部解释，不必把方法编号塞进面向普通用户的主帮助流程。

任务期间显示进度，提供“取消任务”；点击后等待安全停止，不代表瞬间强杀，也不保证撤回已经写出的成功结果。单个测点失败会记录错误，其他测点可继续。结束后可展开运行日志查看错误；存在失败项时显示“仅重试失败测点”，只重新处理失败的当前测点并保留其他成功结果。缺测、复用或深度超差属于已处理结果的状态，不等同于程序失败，不会仅因这些状态自动进入失败重试。

修改配置后要重新处理才得到新结果。旧结果在界面保留，并显示“设置已修改，重新处理后生效；当前显示上次结果”。关闭程序时若有任务或系统文件选择器，会先取消/停止，再完成关闭。

## 9. 输出 CSV 的目录、内容与数值含义

每次运行在保存位置下新建 `OBS处理结果_年-月-日_时分`，例如 `OBS处理结果_2026-10-16_0830`；同分钟已有同名目录时用 `（2）` 等递增，不覆盖之前文件。用户看到的结果目录名称不含 SHA256。每个成功测点生成一个 `<测点编号>#_output.csv`，例如 `1-1#_output.csv`。

CSV 自动随处理保存，没有“先核查再点击导出”的独立必经步骤。结果页的实际按钮名称为“打开结果文件夹”，打开结果下拉框当前所选测点所属的运行目录；当前界面没有另一个名为“打开选中测点目录”的独立按钮。重试后不同点可能分别属于上次和本次目录，应先选对结果测点再打开。

CSV 结构：第一行是输入水深及层位目标等信息；第二行是列名；之后每行对应一个目标整点。不是以第一行直接作为标准列名的单行表头文件。列顺序为：日期、整点、所有层的实际深度、逐层的温度/盐度/浊度。日期含完整年份，整点含时分秒；层数不同，列数也随之变化。

温度、盐度、浊度以及实际深度来自选中的原始观测。程序不插值、不平均、不平滑，不为缺层造值；CSV 的三位小数是输出格式化，不能称为完全保留原字符串精度。当前解析器要求表头明确匹配深度米、浊度 NTU、温度摄氏度、盐度 PSU；不做单位换算。DAT 可读取电导率，但当前结果表和 CSV 的主要输出指标不包含电导率。

CSV 不包含全部来源诊断。程序另外管理核查所需记录；普通用户无需手工整理这些内部文件。技术上，单独复制 CSV 到另一台电脑，并不能据此重建完整曲线与来源详情；当前 GUI 也没有导入历史 CSV 后恢复核查的入口。

## 10. “处理结果”页与问题核查

### 10.1 结果表、筛选、复制和日志

处理完成会进入结果页。顶部摘要的完成/失败按测点计数，缺测/需核查按整点计数。两种整点问题可重叠，不一定能相加成总行数。“完成”是处理流程成功，不等于所有观测质量合格。重试后界面可能同时保留本次与上次条目，应结合下拉框运行时间和来源目录判断。

先在顶部下拉框选测点。表格列为目标时间、状态及各层指标；可按“全部记录”“缺测记录”“需核查记录”筛选，也可把“全部指标”切为深度、温度、盐度、浊度。查找框按目标时间文字匹配，例如输入 `2026-10-16 09`；不是查找原始采样时间。

结果表支持表头排序、滚动和只读查看，主界面测点列表则不排序，不要混为一谈。选中结果行后 Ctrl+C 复制这些行的表格内容；可 Ctrl/Shift 多选结果行。筛选、指标切换和排序只改变显示，不重新计算或改变已导出 CSV。下方显示总行数、当前可见行数和选中目标状态；没有符合条件的记录时应先检查筛选和查找内容。

“展开运行日志/收起运行日志”显示处理日志；小窗口可改为独立日志窗口。日志是查看错误和运行情况的入口，不是要求用户手动执行的命令。

### 10.2 状态定义与后续操作

| 状态/表现 | 含义 | 核查方向 |
|---|---|---|
| 有采样值 | 当前记录有采样数据且没有相应问题提示，不是专业质量合格证书 | 按需要核对层位、时间和来源 |
| 缺少匹配片段 | 该目标整点没有符合匹配条件的观测片段 | 查看原始观测是否覆盖、相邻片段、时间范围与匹配时间差 |
| 缺层 | 已匹配片段但有层位未选到观测 | 查看该片段深度覆盖、水深和规则 |
| 片段复用 | 多个目标整点使用了同一个有效观测片段 | 比较关联整点与片段起止时间，判断是否适合本次业务 |
| 跨层复用 | 不同层位使用同一条原始观测记录 | 检查各层采样、原始行号、实际深度及水深比例 |
| 深度超差 | 相对层的实际深度与目标深度之差超过启用的容差 | 查看偏差、目标深度、实际深度和设置值 |
| 未检查深度偏差是否超限 | 未启用两种深度容差 | 不能解释为偏差为零或已经通过检查 |

“缺测记录”包含缺少片段和缺层；“需核查记录”包含片段复用、跨层复用、深度超差。未启用容差本身不属于该“需核查”筛选集合。复用是需要人工核查的现象，程序允许并提示，不自动认定错误或删除。

共享片段的所有相关目标时间标红，包括首次使用该片段的整点，不只是后面的整点。跨层复用会在“各层采样”中标红相关层名、实际深度及温度/盐度/浊度，且保留“跨层复用”文字。关联关系按完整测点结果计算，不会因筛选只剩一行就变成不复用。

选中有缺测或需核查状态的行，若详情尚未展开，按钮左侧显示红字“展开详情以核查具体问题 →”。提示不会改变右侧按钮大小；展开后提示隐藏。

### 10.3 曲线、各层采样、来源详情

点击“展开曲线与采样详情”，下方有“曲线”“各层采样”“来源详情”三个标签；再次点击收起。小窗口会使用独立“曲线与采样详情”窗口，关闭后回结果页，不必把表格拖成一行来腾地方。分隔条可调高度但不能把区域拖没，“更多 → 恢复默认布局”可恢复布局。

曲线表示时间与深度，并标出匹配片段、选中采样点、峰值和目标整点。蓝色为本次匹配片段，灰色为原始观测或相邻片段。缺口保持断开，不用直线或插值伪造中间观测。

普通记录默认显示匹配片段；片段复用或缺测记录默认扩展到目标前后的有效片段，尽量完整呈现两侧观测。滚轮缩放，底部水平滚动条平移。可浏览范围至少包含目标前后 30 分钟，必要时为完整片段或观测边界进一步扩展，不是任何情况都硬裁成一小时。目标移出当前视野时有边缘方向/日期提示可点回目标。

无前一段/后一段或目标在观测范围外时，显示观测起止边界及留白；这些边界是有效观测范围，不是系统认为此处有缺失数据可补。当前实现保持时间线性比例，不使用假时间压缩，不应把早期“可以不严格按比例”建议写成已经实现的行为。

“恢复全图”只在曲线标签中显示，恢复当前记录的默认视野；不是重置数据、筛选参数或把所有测点曲线叠在一起。曲线基于当次处理记录；旧结果缺少完整曲线资料时会提示只能查看保存的片段，不能假称还原了所有原始数据。

“各层采样”列为：层位、目标深度 (m)、实际深度 (m)、偏差 (m)、实际时间、来源文件、行号、温度、盐度、浊度。偏差是实际减目标的带符号数值，不是百分数。目标整点和实际时间可以不同，目标深度和实际深度也可以不同。表层没有普通相对层的目标深度含义，不应强行补成 0。

“来源详情”说明共用片段的哪些整点、片段的完整起止时间，以及共用原始观测的哪些层、文件路径、行号、实际深度和按当次 H 换算的比例。例如实际深度 2.4 米、H=6 米，则实际比例为 0.4H；它不是目标层标签。缺少旧记录字段时会说明无法还原，不伪造来源。历史结果一律使用当次水深和规则解释，修改当前测点后也不改写历史含义。

## 11. 保存范围、输入格式与功能边界

### 11.1 哪些内容跨启动保留

自定义规则库、窗口尺寸/位置和结果区分隔布局有持久化。当前普通用户 GUI 没有保存/打开项目、导入 JSON 配置、导入 CSV 配置、打开历史结果库的操作入口；重启程序不能指望恢复上次测点列表和全部编辑设置。不要因为源码有配置读写函数就给普通用户编造“文件 → 保存项目”之类菜单。

“开始新一批”保留已生成的文件和规则库，但清掉当前结果预览。历史 CSV 仍可在保存位置用外部软件打开，不代表能从 GUI 重新加载并恢复完整核查窗口。最终交付单文件 EXE 不等于程序运行后不会产生设置、日志或结果文件，也不代表程序是完全无痕的。

### 11.2 当前 DAT 解析约定（技术资料，非必需用户操作）

每份 DAT 必须包含可识别的 OBS 传感器声明，按空白分列。支持的示例（编号不是列序号）：

```text
OBS3A #0000 Firmware Version: 6.20
Sensor                            Data Columns
 1 Depth Mean
 2 OBS-1 (NTU) Mean
 4 Temperature (deg. C) Mean
 5 Conductivity(mS/cm) Mean
 8 Salinity (PSU) Mean
 9 Battery (V) Mean
00:00:00 10/16/2026 4.2 7.5 20.1 1.0 30.2 6.0
```

正文前两列是 `HH:mm:ss MM/dd/yyyy`，随后各列按表中声明的出现顺序对应。每份文件独立识别，即使同一测点不同文件调换了顺序，也不能沿用第一份的映射。必需字段：深度 Depth/Depth(m)、浊度 OBS-1 (NTU)、温度 Temperature (deg. C)/Temperature (°C)、盐度 Salinity (PSU)；名称大小写和空白可有差异。电导率 Conductivity(mS/cm)、电池 Battery(V) 可缺，缺失不补零，也不影响四项必需值读取；未知的非业务传感器仍占一个位置。

仅支持每传感器单列 Mean。重复业务通道、业务字段未知单位/名称、Min/Max 等多列布局、表头缺失、必需字段缺失、正文与表头列数不一致会拒绝；不能靠固定列位置凑数读取。支持 UTF-8（含 BOM）及 GB18030，不支持任意二进制内容改后缀。普通筛选年份须不早于2000；工具校正分析允许早年日期。有限数值/日期错误可记录诊断并跳过，但累计错误超过 max(8,已检查正文行数/20) 拒绝整文件；结构性错误立即失败。测点中任一必需文件不合格，该点不输出部分成功结果，其他合格测点可继续。

普通处理对同时间且深度、浊度、温度、盐度四项数值完全相同的记录去重；电导率、电池不参与身份。同时间不同四项值保留并标冲突，不平均，按时间、来源文件、原始行号排序。校正分析则按原始物理顺序保留所有合法记录，不去重、不排序，检测到时间回跳不允许统一校正。普通采样仍按接近目标的实际观测选取，不插值、不平均。

### 11.3 输入容量与取消

仪器尾部并非观测：`数字 Bytes read from file.`、`File ended without EOF.` 和 `OBS>` 会作为仪器提示记录，不再按传感器列数检查。末尾时间为 `00:00:00 01/01/1970` 或 `23:59:59 12/31/1969` 且所有传感器值为零的记录，只有在其后为上述尾注或文件结束时才视为结束标记；1969形式支持仪器附加的前缀 `1`。它们不参与筛选、水深估算或时间校正，校正保存仍原样保留这些行及尾注。文件内部的早年观测不因年份被当作结束标记，校正分析仍可读取；真正的时间回跳继续拒绝统一校正。未知正文和数据列错位仍报错，不会把所有英文文本一概跳过。`File ended without EOF.` 提示保留在解析诊断中；读取现存观测成功不代表恢复了断电前未保存的数据。

这些是工程保护上限，不能当作仪器能力或采样规范；72小时是典型业务量级，不是时长硬限制。同一秒大量数据仍会消耗预算。当前策略如下，单位 MiB=1,048,576 字节：

| 范围 | 当前限制 |
|---|---|
| 单 DAT / 单点 / 整批累计读取 | 64 / 128 / 256 MiB；有限编码探测的重复读取也计入工作预算 |
| 一次文件选择 / 单点 / 整批文件 | 512 / 256 / 1024 条目；重复实际对象不重复读取，提交条目仍受限 |
| 选文件夹枚举 | 10000 个目录条目；仅确认文件夹后枚举，超限不悄悄截断 |
| 头部 / 单行 / 字段 | 64KiB且最多256行；单行4096字节、最多64列、单字段128字节 |
| 单文件物理行 / 合法观测 | 600000 / 400000 |
| 单点 / 整批观测 | 500000 / 1000000（包括后来去重/点失败前已解析的记录） |
| 单点目标整点 / 动作片段 | 2048 / 4096 |
| 处理成本 | 20000000 次预算单元，覆盖目标×片段与匹配观测×层数，不等同于实际CPU指令 |
| 完整曲线输入 / 校正预览绘制 | 500000 / 最多8001点；绘制抽样不作为业务导出或匹配数据 |
| JSON | 一般128MiB、最多6000000节点、嵌套32层；规则库1MiB、256条规则；校正通信8MiB |
| 输出 | 单个原子写出文件128MiB；诊断错误样本最多256条，计数可更多 |
| 日志 | 每种内部任务角色2MiB轮转并保留1份，故障栈保留最近8份（活动文件除外） |
| 分析时间 | 180秒检查预算；普通处理/水深分析进程约190秒兜底中止；校正提交不强制杀进程 |

超过容量应缩小本次实际输入或测验范围，不能把被截断的部分冒充完整输出。超大文件先按元数据拒绝，再进行有界头部及正文校验；不是先整文件加载/哈希后才拒绝。后台支持取消，原生选择器打开时主界面仍由独立进程管理。源文件在读取期间变化、无权限、格式不符、过大、超时会显示原因，不应使整个程序退出。程序自身不在系统选择器确认前读取 DAT；Windows/OneDrive 自身的浏览行为及在线占位文件仍须目标环境验证。

### 11.4 常见疑问的事实答案

| 疑问 | 应据此作答的事实 |
|---|---|
| 未勾选测点为何也处理了？ | 开始处理针对列表全部测点，勾选只用于批量设置/移除 |
| 新建规则为什么没改变层数？ | 创建只保存到库，还需回单点/批量窗口选择并应用 |
| 改 H 后层数为什么不变？ | 当前可能是固定系统规则或自定义规则；需选回自动才跟随水深 |
| 取消高级设置后新规则为什么还在？ | 规则库独立即时保存；取消只撤销尚未应用的参数设置 |
| 自动水深为何没有立即出现？ | 导入、编辑、保存都不估算，开始处理时才估算 |
| 为什么 08:23 开始的处理没有 08:00？ | 显式开始时间向上取目标整点 |
| 为什么所选时间外的记录也被用到？ | 时间限制控制目标整点，分段/匹配仍使用完整输入观测 |
| 曲线有数据，整点为何仍缺测？ | 有原始观测不等于存在符合识别和时间匹配条件的有效片段 |
| CSV 行数为何比界面少？ | 检查是否勾选仅导出各层齐全整点；界面保留完整结果供核查 |
| 结果为什么全空或查不到？ | 先检查结果测点、筛选、查找文字及目标时间范围，再核查日志/原始数据 |
| 是否需要核查后再导出？ | CSV 已随处理自动保存；核查后改配置并重新处理，产生新目录 |
| 重启后测点列表为何没了？ | 当前 GUI 没有项目自动恢复/保存入口，需重新添加和配置 |
| 结果为空是否等于仪器测得零？ | 不等于；缺测留空，程序不补零 |

## 12. 实用工具：时间校正向导

主界面右上角“实用工具”打开独立窗口，首页仅有“时间校正”一项宽栏入口，左侧图标、标题、说明和空白属于同一按钮。整栏可点击，Tab可聚焦，Enter/空格可激活；没有未来工具占位。进入后在同一窗口切换四步页面，不再使用工具选项卡或额外最终确认对话框。主处理运行中不可启动校正；校正任务运行中不可开始主处理。

顶部显示“第x步，共4步”和当前标题，不可点击越级。底部常驻“上一步 / 下一步 / 取消”，第1步禁用上一步，第4步将下一步改为“确认修改”。完成页改为“返回工具列表 / 关闭”。小窗口中主体可滚动，导航不随曲线或表格滚动。日期/时间继续复用测点编辑的定制浮层；已知时间保留秒精度，抛测起止使用下述整点模式。

| 步骤 | 操作与保存时机 |
|---|---|
| 1. 选择文件 | 点“选择DAT文件”调用Windows原生打开框，明确选择一份文件；与主列表勾选无关。后台只读校验通过后显示完整路径、有效观测数、原始范围和识别列，才能下一步。取消选择不改变会话；同一会话重选同一或其他文件保留正确时间、测验起止及方式草稿，重新读取仪器参考时间。分析、缺测分配、保存目标及最终许可清除，并提示核对草稿适用性。格式错误留在此页重新选文件，不伪造预览。 |
| 2. 设置校正方式 | 选择两种方案之一，只显示相应的两组时间输入。“已知时间对应关系”中的仪器时间可预填文件首条有效观测，正确时间不猜测为今天；另一方案的实际起止整点由用户填写。输入合法后点下一步只读分析。 |
| 3. 核对结果 | 原/新范围、时差、方案和假设为简短摘要，曲线默认可见并占主要空间。“恢复全图”位于曲线工具栏右侧；“展开对应明细”默认收起，展开后显示可滚动对应表，选择行定位目标。需首尾分配或质量不合格仍可查看曲线与原因，但下一步禁用；格式/读入失败返回发起分析的可编辑步骤。有效方案经用户核对后点下一步。 |
| 4. 确认修改 | 展示完整源路径、方案与范围摘要、缺测假设、备份安排，红色加粗“将修改原始 DAT 文件”；仅点击“确认修改”才保存。上一步回核对，取消回工具列表，均不写文件。为避免上页双击误写，进入此页或更换目标后确认按钮短暂禁用；Enter不会触发默认写入，必须独立主动操作确认按钮。 |
| 完成 | 区分原位/另存，列出实际输出路径和已创建备份；另存明确没有新增原始备份。无可重复保存的下一步或上一步，可返回工具列表建立新会话，或关闭。 |

**已知时间对应关系**：填写同一时刻的“仪器记录时间”和“实际正确时间”，整份有效观测统一增加两者之差。允许早年、正负或零偏移、跨日跨年/闰日；不改变记录间隔和数值。文件时间回跳、无效日期或必需数据错误不能用一个时差统一修正。

**按抛测规律匹配**：填写实际测验“开始整点”“结束整点”，含首尾。日期保留完整年份；时间输入只接受0—23的小时，旁边固定显示`:00:00`，时间浮层的分、秒固定00且不可操作。非整点整串粘贴不接受，不截断或自动归整；程序设置已有非整点值会拒绝并保留原值。切换方式不修改已知时间草稿，主界面其他时间控件仍保留秒精度。

此模式独立整理受支持的候选片段：持续浅水停留/真断档分开的各过程独立估计进入阈值，避免较深过程遮掉较浅过程。连续近邻片段之间只有小回撤，或一两条短暂浅值且迅速回到此前深度范围时可组成同一动作，采用组内最深受支持时刻；等深取文件顺序最早观测。一条和两条浅值都须符合附近正常采样节奏：含两侧返回点的耗时不得超过附近正采样间隔中位数的3倍，前后各检查最多3个间隔且各至少有一个正间隔；任一侧证据不足或长停留均只读提示分界不确定，不能按短误差处理。真实观测断档不合并，有连续浅水停留证据的候选保留独立；较深且持续的回撤缺乏明确分界时只读提示不确定，不自动保存。识别依据及局限见ALGORITHM的校正专用说明，不能将自动识别当作现场动作已获证明。第一完整动作仍对齐开始加开头缺测数，整文件只平移一个时差。动作间隔距整数小时偏差、平移后锚点距目标整点残差均允许15分钟（含边界）；近邻未能合并的动作不会强制各推进一小时，同一目标冲突明确标记并拒绝写入。这些不是普通采样容差，普通水深建议、采样及CSV算法未改变。

核对曲线中空心圆为原候选、实心方块为整理后动作最深锚点。展开对应明细除逐目标对应表外，还显示每个动作的候选编号、最深时刻/深度、完整来源路径/行号、合并依据，以及每个候选起止和不确定说明；明细时刻为仪器原始时间，曲线采用统一平移后的时间。选择表格行会将对应目标移入可见视野，尽量保持当前缩放跨度并同步滚动条。最大浏览范围及“恢复全图”覆盖观测范围与全部目标整点并留边缘空白，首尾缺测目标也能定位；文件真实起止另行标注，边界外不补观测。

需要首尾缺测分配时，核对页曲线上方显示“开头缺测次数”“结尾缺测次数”；两者之和须等于剩余次数，点“确认首尾缺测并重新预览”。确实不记得时可主动选择“不记得，按开头无缺测处理”，不能把关闭/取消当作同意。确认后收成首尾数量/假设摘要，提供“修改缺测分配”；修改立即使旧匹配和写入许可失效，重新分析前不可下一步。对应表逐目标显示目标整点、动作序号/原始代表时刻、平移后残差秒数和状态。缺测与异常按目标去重统计，达到目标数一半、动作过多、时序超范围、间隔不可靠等均不能写入；不会删动作、逐段拉伸以凑整点。

单纯上一步保留输入和已有分析，再前进不重复分析或读入大文件。修改方案/时间、换文件或修改缺测使相关分析及最终确认失效，旧曲线清除，不能当作新结果提交；最终保存前仍重新核对源文件与方案，缓存不能绕过这一检查。迟到的旧任务回调、取消或关闭后回调不能覆盖新会话。分析中显示忙碌进度及“取消任务”，导航和输入禁用；取消等待安全结束，回到发起分析的可编辑步骤，输入保留，DAT未写入。空闲向导“取消”结束会话回首页；窗口关闭结束工具。再入时间校正不继承旧文件、草稿或保存许可。

前三步不备份、不修改DAT。原位保存先独占创建完整原始备份，如 `A.dat.bak`，重名用 `.bak.1` 等递增，不覆盖旧备份；校验后安全替换，仅修改有效观测行开头日期时间，其余表头、数值、结束记录及尾注字节保留。提交后验证失败尝试从备份恢复，备份是用户资产。提交阶段禁用取消，关闭窗口会等待安全结束，不能强杀替换/回滚进程。

原位保存失败停在第4步显示原因，可点“选择保存位置后重试”，调用Windows原生保存框。必须用未存在的新DAT文件名，不能选择源文件或其他已有文件。选中目标后仍回第4步，红字改为“将另存校正后的 DAT，原文件保持不变”，展示目标；选择路径本身不写入，仍须再次“确认修改”。保存框取消/Esc/关闭只回第4步并保留预览和输入，不退出整个会话；另存再次失败也留在此页。第4步向导取消才回首页。失败不包装为完成，不自动另存或重试。

原位成功后，主界面相关输入的自动估算及背景曲线缓存失效，人工水深和历史结果快照保留，旧结果标为需要重新处理。另存不自动替换主测点文件关联，要用新文件应重新设置数据文件。必须重新处理才能生成对应新CSV。普通筛选不修改DAT，时间校正最终确认是例外；断电前未保存的数据不会被恢复。真实业务校正与目标环境验收见 ROADMAP。

## 13. 给帮助撰写者与维护者的约束

帮助文案可据本文调整篇幅和结构。面向最终用户时，应使用实际按钮名称、明确操作对象和保存时机，优先覆盖导入、单点/批量配置、开始处理、水深确认、结果核查和 CSV 查阅。技术算法、实现路径、测试数字和内部记录存储无需照搬到帮助中。

文案核对重点：起止时间可按当前规则留空；保存位置在开始处理前选择；CSV 在处理时导出；缺测/需核查按目标整点统计；测点规则在单点/批量编辑中分配；没有独立“打开选中测点目录”按钮；当前设置不会自动保存为可重开的项目。

本文描述的是实现事实，不是全部场景均已验收的承诺。当前验证范围与待验收事项集中在 ROADMAP.md；真实数据、仪器单位、规范版本、目标 Windows 电脑及许可事项未确认的，不在帮助中补成已确认结论。GUI 没有 WinUI 3 原生框架依赖，当前用 Python + PySide6 定制 Fluent 风格；无需让最终用户理解此技术栈。

维护源码时应同步更新本文中受影响的入口、默认值、状态、例子和功能边界，保持正文自包含，不能只留“详见源码”的链接。任何贡献者均可提交用户帮助改进，更新时核对 `docs/help_inline.txt` 与程序内文案的一致性，并在 PR 中说明对应的界面行为。
