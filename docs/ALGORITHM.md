# 算法原理与业务输出规则说明 (`ALGORITHM.md`)

本文档面向开发者与算法审阅者，完整记录 `src/obs_tool/` 当前实际执行的**数据读取、参考水深推算、观测片段切分、整点垂向分层选点、质量复核投影**以及**单文件仪器时间校正**算法规则。

- 当前核心采样算法版本标识为 `custom-layers-3`（定义于 `src/obs_tool/__init__.py`）。
- 算法核心模块（`readers.py`、`algorithm.py`、`processing.py`、`depth.py`、`correction_actions.py`、`time_correction.py`）仅依赖 Python 标准库，与 PySide6 图形界面完全解耦，由后台子进程调用。
- **“实用工具 → 时间校正”** 是在用户最终确认后对单份 `.dat` 文件时间戳执行的一次性全局平移，不属于常规采样筛选流程的一部分；常规批处理全程只读访问原始 `.dat` 文件。

---

## 1. 批处理准备阶段与水深自动估算 (`depth.py` / `depth_workflow.py`)

### 1.1 按需估算与人工确认门禁
1. **导入不立即估算**：用户在主界面导入 `.dat` 文件或修改测点配置时，软件不会在主线程读取文件计算水深；新导入测点默认 `depth=None`、`depth_source="pending"`。
2. **处理前后台估算**：点击“开始处理并导出 CSV”后，仅针对 `depth is None` 的测点启动后台子进程执行 `supported-cast-peaks-median-v1` 算法；已手动填写水深（`depth_source="manual"`）的测点直接采用人工值，绝不被自动估算覆盖。
3. **集中人工确认**：当估算结果标记为需要核实（见 1.2）时，GUI 在正式批处理前弹出“水深填写与确认”窗口，经用户逐行确认或填入实测正数水深后继续处理。
4. **稳定测点身份（`point_id`）**：每个 `Point` 拥有不可编辑的 UUID 身份 `point_id`，与用户可修改的测点编号 `code` 分离；加载缺少 `point_id` 的旧版配置时自动补齐。

### 1.2 参考水深估算方法 (`supported-cast-peaks-median-v1`)
该算法独立于后续整点采样分段，不依赖任何预设总水深 $H$：
1. **过滤与三点支撑检查**：保留深度非负且有限的记录（包含零深度）；某条记录若要成为“受支撑观测”，其前后相邻记录的时间间隔均不得超过 `5 分钟`，且前后相邻深度均须至少达到该点深度的 `50%`（剔除孤立单点毛刺）。
2. **包络与入水分组阈值**：取所有受支撑观测深度的 `99%` 分位数作为深度包络 `envelope_m`，以 `max(0.10 米, 0.35 × envelope_m)` 作为入水深度阈值 `threshold_m`。
3. **有效下放剖面（Cast）切分与中位数聚合**：将深度达到 `threshold_m` 且相邻间隔 $\le 5$ 分钟的连续观测归为一次下放剖面，提取每次剖面内的最大受支撑深度作为峰值（保留来源文件与物理行号），取全部剖面峰值的**中位数**，使用 Python `round(..., 3)` 保留 3 位小数，作为建议参考水深 $H$。
4. **可信度与人工复核判据**：
   - 当识别出的有效下放剖面少于 `3` 次、各次峰值深度的四分位距（$\mathrm{IQR} = Q_{75} - Q_{25}$）超过建议水深的 `20%`、或文件存在同秒不同数值冲突（`timestamp_conflicts > 0`）时，可信度记为 `"需核对"`，触发界面确认弹窗；
   - 若有效观测不足导致无法给出正数建议值，估算返回 `value=None` 及原因，要求用户人工填入实测水深；不生成 `"unavailable"` 来源值。
   - *注：若现场施测时探头未下放至水底，观测数据本身无法证明真实总水深；自动估算值仅作工程辅助建议，不构成水文测验规范的最终水深定论。*

## 2. 观测片段切分、整点匹配与垂向分层选点 (`algorithm.py` / `processing.py`)

### 2.1 分段阈值与前后缓冲规则 (`build_segments`)
1. **分段深度阈值**：在测点的全部有效观测记录上计算深度的 `20%` 分位数 $Q_{20}$ 与 `90%` 分位数 $Q_{90}$，结合测点参考水深 $H$ 与最低参考深度 `min_depth`（默认 `0.10` 米）构造阈值。先令 $L=\max(\text{min\_depth},Q_{20})$、$U=\max(L,Q_{90})$、$S=\max(U-L,0.15H,0.5)$：
   - **进入阈值 `start_threshold`**：$\max(\text{min\_depth}, L+0.65S, 0.35H)$；
   - **停止阈值 `stop_threshold`**：$\max(\text{min\_depth}, L+0.45S, 0.25H)$；
   - **边缘裁剪阈值 `resume_threshold`**：$\max(\text{min\_depth}, L+0.30S, 0.20H)$。
2. **片段起止与断档切分**：
   - 当观测深度 $\ge \text{start\_threshold}$ 时激活当前片段。闭合时裁剪低于 `resume_threshold` 的首尾边缘，并拼接 `pre_minutes`（默认 `8` 分钟）窗口内**严格早于核心起点**的前缓冲记录；
   - 相邻观测时间间隔超过 `gap_minutes`（默认 `5` 分钟）时强制结束当前片段；
   - 片段激活期间，若深度连续低于 `stop_threshold` 达到 `stop_count`（默认 `4` 个点），则闭合当前片段；遇到不低于 `stop_threshold` 的记录时低值计数清零。
   - **后缓冲裁剪语义**：片段结束时，对尾部已纳入 `active` 列表的低深度拖尾记录最多保留 `tail_minutes`（默认 `8` 分钟），并非在片段结束后再继续向后读取未来 8 分钟的数据。
3. **起止时间窗口与分段的关系**：测点配置的 `start` / `end` 仅限定**需要生成哪些目标整点**，时间窗口外相邻的原始观测记录仍完整参与片段切分与整点匹配。

### 2.2 目标整点序列与片段峰值匹配 (`process` / `choose_segment`)
1. **目标整点生成**：
   - 未指定开始时间时，从首条有效观测所在小时整点开始；显式指定开始时间时**向上取整点**（如 `08:23:00` 首整点为 `09:00:00`，`08:00:00` 则包含 `08:00:00`）。
   - 未指定结束时间时，至末条有效观测所在小时整点结束；显式指定结束时间时**向下取整点**（包含不晚于该时刻的整点）。
   - 单测点最多允许生成 `2048` 个目标整点，防止误填跨年时间跨度。
2. **最深峰值（Apex）匹配**：
   - 每个有效观测片段以其内部实测最大深度记录的时刻作为峰值时刻 `apex`（等深时取较早记录）。
   - 在满足 $|\text{apex} - \text{目标整点}| \le \text{max\_offset\_minutes}$（默认 `60` 分钟，含边界）的候选片段中，选取时间差最小的片段；时间差相同时优先选取 `apex` 较早的片段。
   - 允许多个目标整点匹配到同一个观测片段（策略固定为 `allow_warn`），此时自动标记 `"segment_reused"`（片段复用）供人工复核。

### 2.3 垂向分层方案与各层选点规则 (`get_layer_plan` / `select_depth_matches`)
1. **三种分层模式**：
   - **按水深自动选择（`layers=None, layer_positions=None`）**：
     - $0 < H < 2\text{ m}$：**1 层**（`0.6H`）
     - $2 \le H < 5\text{ m}$：**2 层**（`0.2H`、`0.8H`）
     - $5 \le H < 8\text{ m}$：**3 层**（`0.2H`、`0.6H`、`0.8H`）
     - $8 \le H < 11\text{ m}$：**5 层**（`表层`、`0.2H`、`0.6H`、`0.8H`、`底层`）
     - $H \ge 11\text{ m}$：**6 层**（`表层`、`0.2H`、`0.4H`、`0.6H`、`0.8H`、`底层`）
   - **固定系统规则（`layers in {1, 2, 3, 5, 6}`）**：显式锁定上述某档系统层数，后续修改水深 $H$ 时层数不再跳变。
   - **自定义相对层位规则（`layer_positions`）**：由 1～64 个严格升序、位于 $[0, 1]$ 区间的比例组成；其中 `0` 映射为表层，`1` 映射为底层，其余数值 $r \in (0, 1)$ 映射为目标深度 $r \times H$ 的相对层。
2. **各层选点算法**：
   - **表层（`surface`）**：从当前匹配片段内实测深度**严格大于** `surface_min`（默认 `0.5` 米）的观测中，选取使综合加权评分最小的记录：
     $$\text{Score} = w_{\text{depth}} \times \text{depth} + w_{\text{target}} \times \frac{|\text{timestamp} - \text{target}|}{60} + w_{\text{start}} \times \max\left(0,\ \frac{\text{timestamp} - \text{segment\_start}}{60}\right)$$
     默认权重为 $w_{\text{depth}}=1.0$、$w_{\text{target}}=0.1$、$w_{\text{start}}=0.05$。
   - **底层（`bottom`）**：直接选用当前匹配片段内的最深实测记录 `segment["deepest"]`。
   - **相对水深层（`relative`，如 `0.2H`～`0.8H`）**：在当前片段内按 $|d - r \cdot H|$ 深度偏差最小原则依次为各相对层选点，且**不同相对层之间尽量不重复占用同一条真实观测记录**（并列时保持近似相等比较并优先选取较早时刻）。若表层或底层与某个相对层选到了同一条物理记录，或片段内可用记录少于相对层数，程序如实标记 `"cross_layer_reused"`（跨层复用）或 `"missing_layer"`（缺层），绝不插值或伪造数据。

### 2.4 深度偏差容差与结果核查显示投影 (`result_projection.py`)
- **深度质量判定**：对每个相对层计算带符号偏差 $\Delta d = d_{\text{实测}} - d_{\text{目标}}$（米）。当启用了绝对容差 `tolerance_m` 和/或相对容差 `tolerance_ratio`（按**当前层目标深度**的比例计算，而非总水深 $H$ 的比例）时，若两者同时启用则取更严格的上限（等于上限视为通过）；超出上限时保留原采样值并标记 `"depth_out_of_tolerance"`。若两者均未启用，则标记 `"tolerance_unset"`。
- **结果页只读反向索引（`ReviewProjection`）**：为了在界面上将**首次使用某共用片段的目标整点**也一并高亮标红，`ReviewProjection` 在完整测点结果上构建片段被引用次数与物理记录 `(来源文件绝对路径, 物理行号)` 被引用层位的反向索引。该投影仅服务于界面渲染，不改动底层算法状态或已导出的 CSV 文件。

## 3. DAT 动态表头解析、尾注剔除与资源预算 (`readers.py` / `input_policy.py`)

1. **逐文件独立解析表头**：
   - 每份 `.dat` 文件必须包含 `Sensor Data Columns` 表头，仅支持每通道单列 `Mean` 平均值格式。
   - 必需四项业务通道：`Depth (m)`、`OBS-1 (NTU)`、`Temperature (deg. C / °C)`、`Salinity (PSU)`；可选通道：`Conductivity (mS/cm)`、`Battery (V)`。
   - 同一测点关联的多个文件必须**全部合格**；任一文件若缺少表头、缺失必需通道、列宽不符或超出坏行容忍上限（$\max(8,\ \text{已检查正文行数} \div 20)$），该测点整体报错停止导出，绝不静默跳过坏文件后导出残缺结果。
2. **仪器尾注与结束标记行剔除**：
   - 自动识别文件末尾的仪器统计与命令提示行（`<数字> Bytes read from file.`、`File ended without EOF.`、`OBS>`）并记入解析诊断，不作为数据列宽错误。
   - 紧邻尾注或文件末尾之前的全零 `00:00:00 01/01/1970` 或 `23:59:59 12/31/1969`（允许带前缀 `1`）记录作为仪器结束标记剔除；文件内部正常的早期年份记录不受影响。
3. **去重与同秒冲突处理**：
   - 常规批处理要求观测年份 $\ge 2000$（时间校正分析允许更早年份以便修复未校时仪器数据）。
   - 时间戳与深度、浊度、温度、盐度四项必需值**完全相同**的重复记录自动去重（保留按文件路径排序最先读取的记录）；同一秒内四项必需值存在差异的记录全部保留，按 `(timestamp, file, line)` 稳定排序并记录 `timestamp_conflict` 诊断。

## 4. 单文件时间校正与完整抛测动作识别 (`correction_actions.py` / `time_correction.py`)

### 4.1 两种校正模式
1. **已知时间对应关系（`known`）**：根据用户给定的同一采样时刻的“仪器记录时间 $t_{\text{inst}}$”与“实际正确时间 $t_{\text{real}}$”，计算全局唯一平移秒数 $\Delta t = t_{\text{real}} - t_{\text{inst}}$，对全文件所有有效观测行统一加上 $\Delta t$。若文件内部存在时间倒退（回跳）或存在格式/数值损坏行，拒绝执行校正。
2. **按抛测规律匹配（`casts`，算法标识 `supported-local-candidates-continuity-v1`）**：
   - **局部包络与候选片段提取**：先按超过 `5 分钟` 的真实时间断档或连续 $\ge 3$ 条深度 $\le 0.10$ 米的浅水停留将观测序列切分为独立观测过程，在每个过程内独立计算 `99%` 分位数包络与 `35%` 入水阈值（$\ge 0.10$ 米），提取满足三点支撑的原始下放候选片段（`candidates`），避免深水抛测过程抬高全局阈值而吞没浅水抛测过程。
   - **近邻候选合并为完整抛测动作（`actions`）**：当相邻两个候选片段的最深时刻相距 $\le 15$ 分钟且其间无超过 5 分钟断档、无连续 3 点 $\le 0.10$ 米浅水停留时：
     - 若过渡期最浅回撤深度不低于前候选峰值的 `50%`，合并为同一次抛测动作；
     - 若过渡期仅出现 `1 ~ 2` 条低于前峰一半的短暂浅值，且浅值前后紧邻点均达到前峰一半、包含两侧正常点在内的总耗时不超过周围正常正采样间隔中位数的 `3 倍`（前后各取最多 3 个非零间隔，且两侧均至少有 1 个正间隔证据），同样合并为同一次抛测动作；
     - 若出现 $\ge 3$ 条深回撤、或 1～2 条浅值停留过久 / 缺乏两侧采样节奏证据，则标记为**抛测分界不确定（`uncertainties`）**，仅允许在界面只读核查曲线，禁止写回修改文件。
   - **整点对齐、缺测分配与残差校验**：
     - 设测验开始至结束整点共 $N$ 个目标整点，识别出 $M$ 个完整抛测动作。当相邻动作间隔距最近正整数小时偏差 $\le 15$ 分钟时，中间跳过的整点数计入中间缺测 $I$；剩余首尾缺测总数 $R = N - M - I$。
     - 若 $R > 0$，要求用户显式分配“开头缺测次数”与“结尾缺测次数”（或主动选择“不记得，按开头无缺测处理”）。
     - 以首个动作对齐 `开始整点 + 开头缺测小时数` 确定唯一全局时差 $\Delta t$，要求平移后各动作距目标整点残差 $\le 15$ 分钟（含边界）。若近邻动作间隔四舍五入为 0 小时（同目标冲突）、异常整点数达到总目标数一半（$2 \times \text{问题数} \ge N$）、存在分界不确定或动作超出范围，均拒绝写入文件。

### 4.2 原位备份、原子替换与回滚保证 (`save`)
- 保存前重新核对源文件大小、行数与 SHA-256 指纹，确保预览后源文件未被外部改动；
- 流式生成同目录临时文件，仅替换有效观测行开头的日期与时间文本，严格保留原始表头、数值字符串、空白、编码、换行符与尾部仪器提示；
- 重新调用解析器复验临时文件的记录数、首尾时间与数据完整性；
- 原位保存前先独占创建完整的 `.bak` 原始备份（如已有 `.bak` 则递增为 `.bak.1`、`.bak.2`，绝不覆盖旧备份），再原子替换原文件；若替换后最终复验失败，立即从备份恢复原文件。
